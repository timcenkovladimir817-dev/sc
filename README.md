# Арматура PRO — модульный проект

## Запуск
GitHub Pages: загрузите СОДЕРЖИМОЕ этой папки в корень репозитория. index.html должен лежать в корне. Settings → Pages → Deploy from a branch → main → / (root).
Локально: установите Python, откройте терминал в этой папке, выполните `python -m http.server 8000`, затем откройте http://localhost:8000.
Двойной щелчок по index.html не поддерживается: браузер блокирует загрузку JSON через file://.

## Учётные записи и админка
- `login.html` — вход; `reset.html` — задание пароля по ссылке из письма.
- `admin/index.html` — обзор, статистика и приглашение сотрудника.
- `admin/users.html` — роли, блокировка, сброс пароля, ссылки на прогресс, CSV-экспорт, напоминания о сроках.
- `admin/stats.html` — статистика по каждому ученику: главы, тест, активность, время на курсе, просрочка.
- `admin/audit.html` — журнал действий администратора (только чтение).
- `admin/diag.html` — диагностика доступа: сессия, профиль, роль, таблицы, функции.
- `progress.html` — прогресс по токену для наставника и руководителя.

Первый администратор создаётся вручную: Supabase → Authentication → Users → Add user,
затем `supabase/bootstrap-admin.sql` с его email. Подробно — `docs/SETUP.md`.
Ключ `service_role` хранится только в секретах Supabase, не в `js/config.js`.

Миграции выполняются по порядку: `0001` → `0002` → `0003` → `0004` → `0005` → `0006` → `0007` → `0008` → `0009` → `0010` → `0011`.
Edge Functions: `invite-user`, `resend-invite`, `block-user`, `send-reminders`.

Роли: `admin` — администратор (всё управление), `teacher` — наставник (приглашает учеников,
следит за прогрессом, дополняет материал, выгружает результаты), `student` — ученик (проходит курс).
Учебные материалы открываются только после входа; ученику без назначенного курса они недоступны.

Назначение курса: администратор и наставник могут назначать сотруднику курс целиком или
отдельные главы (блоки) — при приглашении (форма «Пригласить сотрудника») и уже созданному
пользователю (кнопка «Назначить» в разделе «Пользователи»). Пустой набор глав = весь курс.

## Оформление
Кнопка «⚙» справа внизу на каждой странице: тёмная/светлая тема (или «авто» по системе)
и размер текста. Настройки хранятся в браузере. Логика — в `js/theme.js`.

## Главы 17–20: материалы презентаций
Четыре главы добавлены по циклу презентаций «Тема 1–4» и используют извлечённые из них иллюстрации:
- `17` — номинальные диаметры и давления, виды присоединений;
- `18` — опросный лист: давление, расход, герметичность, приводы;
- `19` — классификация арматуры по назначению;
- `20` — электроприводы и пневмоприводы, крутящий момент и подбор.

Картинки лежат в `images/kma/` с префиксом темы (`t1-…`, `t2-…`, `t3-…`, `t4-…`). Они указаны в разделах глав и внесены в `content/project-files.json`, поэтому попадают в ZIP-экспорт. Исходные PPTX остаются в папке вложений и в ZIP-экспорт не входят: при обновлении материалов замените изображения файлами с теми же именами.

## Что где менять
- `content/modules/01-module.json` … `20-module.json` — каждая глава отдельно: title, hours, goal, sections, table, task, answer, checks, links, images. Раздел с иллюстрацией: `[заголовок, текст, [["graphics/схема.svg", "подпись"]]]`.
- `content/book.json` — название и список файлов глав, их порядок. Для новой главы создайте JSON и добавьте путь в этот список.
- `content/quiz.json` — итоговый тест. Строка вопроса: [вопрос, [варианты], индекс правильного с нуля, объяснение].
- `content/standards.json` — ГОСТы: [номер, название, URL или null]. Проверяйте актуальность и применимость.
- `css/style.css` — цвета, шрифты, размеры, мобильное оформление.
- `graphics/` — самостоятельные SVG-схемы; можно открыть в Inkscape или изменить текст SVG.
- `images/` — ваши фотографии и иллюстрации. Пример записи главы: "images": [{"data":"images/seat.jpg", "caption":"Повреждение седла"}]. Используйте имена латиницей без пробелов. Готовые иллюстрации из презентаций — в `images/kma/`.
- `js/app.js` — отображение, переходы и тестирование.
- `js/admin-nav.js` — общая навигация админ-панели.
- `js/supabase-client.js` — клиент Supabase, проверка администратора, вызов функций.
- `js/theme.js` — тёмная тема и размер текста.
- `supabase/` — миграции, функции приглашений и SQL для первого администратора.
- `docs/SETUP.md` — настройка учётных записей, приглашений, почты и Bitrix24.
- `js/calculations.js` — инженерные расчёты: Kv, подбор фланца и прокладки, рабочее давление по PN и температуре, DN по расходу.
- `js/editor.js` — встроенный редактор.
- `js/export.js` — сборка ZIP-проекта без сторонних библиотек.
- `js/loader.js` — загрузка материалов и запуск.

## Калькуляторы
Раздел «Калькуляторы» содержит четыре вкладки:
- **Kv жидкости** — требуемая пропускная способность по формуле `Kv = Q × √(SG / Δp)`.
- **Фланец и прокладка** — требуемый PN по ГОСТ 356-80 с учётом температуры, ближайший PN по ГОСТ 33259-2015, исполнение уплотнительной поверхности, прокладка по ГОСТ 15180-86 / ГОСТ 34655-2020 и тип фланца.
- **PN по температуре** — допускаемое рабочее давление для выбранного PN и материала при заданной температуре.
- **DN по расходу** — расчётный диаметр и ближайший стандартный DN, фактическая скорость среды.

Подбор учитывает категорию среды (негорючие, взрывоопасные, вредные вещества, ВОТ, вакуум, фреон/аммиак/водород) и примечания к таблицам. Результат предварительный: проверяйте проект, паспорт изделия, каталог изготовителя и химическую стойкость прокладки.

## Редактирование без кода
Откройте Редактор книги, измените главу, сохраните. Кнопка «Скачать только главу JSON» выдаёт файл для замены соответствующего файла в content/modules. После перестановки глав или изменения структуры используйте «Скачать весь проект ZIP»: он обновляет и список, и главы.
Распакуйте ZIP и загрузите содержимое в репозиторий. Редактор не имеет доступа на запись в GitHub. Сохранение в браузере не публикует изменения.
Оставляйте резервную копию JSON перед крупными правками.

## Важное
Материалы перенесены из версии 4; это не новая нормативная экспертиза. Критерии и числовые параметры проверяются по документации изделия.
Редактор доступен всем посетителям; доступа к репозиторию он не даёт. Прогресс и правки хранятся локально. При обновлении содержания локальная редакция может перестать подхватываться — сначала экспортируйте её.
Загруженные редактором картинки пока хранятся внутри JSON как data URL. Для полностью отдельных файлов положите фото в images/ и укажите путь в JSON.
Добавленные главы получают вопросы самопроверки, но итоговый тест изменяется отдельно в quiz.json.
`content/project-files.json` — перечень статических файлов для ZIP-экспорта. Если добавили собственный CSS/JS, внесите путь туда и подключите файл. Фотографии из images/, указанные в главах, экспортируются автоматически.
Проект не является системой аттестации и не заменяет практику или допуски.
