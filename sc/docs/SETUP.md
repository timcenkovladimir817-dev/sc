# Арматура PRO — учётные записи, приглашения и прогресс

Первый рабочий блок: **закрытая регистрация по приглашению**, роли, прогресс, задача в Bitrix24 и письма через Яндекс.

## Что входит

| Компонент | Назначение |
|---|---|
| `supabase/migrations/0001_init.sql` | Таблицы, роли, RLS, ссылки на прогресс |
| `supabase/migrations/0002_seed_course.sql` | Курс и 16 модулей |
| `supabase/functions/invite-user` | Приглашение, задача Bitrix24, письмо |
| `supabase/functions/resend-invite` | Повторное приглашение |
| `supabase/functions/block-user` | Блокировка входа |
| `admin/index.html` | Панель приглашений |
| `progress.html` | Прогресс по ссылке для наставника и руководителя |

## Порядок настройки

### 1. Supabase

1. Создайте проект на supabase.com.
2. SQL Editor → выполните `0001_init.sql`, затем `0002_seed_course.sql`.
3. Authentication → **Users → Add user** — создайте себе первого администратора с email и паролем.
4. В таблице `profiles` у этой записи задайте `role = admin`.
5. Authentication → Providers → Email: **отключите «Allow new users to sign up»**.
6. Authentication → URL Configuration: Site URL и Redirect URLs — адрес вашего сайта, включая `/reset.html`.

Ключ `service_role` не публикуйте. Он используется только в секретах функций.

### 2. Секреты функций

В Supabase → Edge Functions → Secrets задайте:

```text
SITE_URL=https://timcenkovladimir817-dev.github.io/sc
ALLOWED_ORIGIN=https://timcenkovladimir817-dev.github.io
BITRIX_WEBHOOK_URL=https://ваш-портал.bitrix24.ru/rest/1/xxxxxxxxxxxx/
YANDEX_SMTP_USER=training@ваша-компания.ру
YANDEX_SMTP_PASSWORD=пароль-приложения
YANDEX_SMTP_HOST=smtp.yandex.ru
YANDEX_SMTP_PORT=465
MAIL_FROM_NAME=Учебный центр
```

Для Яндекса нужен **пароль приложения**, а не обычный пароль от почты. Он создаётся в настройках аккаунта Яндекс 360.

`SUPABASE_URL`, `SUPABASE_ANON_KEY` и `SUPABASE_SERVICE_ROLE_KEY` Supabase передаёт функциям сам.

### 3. Публикация функций

```bash
supabase functions deploy invite-user --no-verify-jwt
supabase functions deploy resend-invite --no-verify-jwt
supabase functions deploy block-user --no-verify-jwt
```

Функции сами проверяют токен пользователя и роль администратора. `--no-verify-jwt` нужен, потому что проверка выполняется внутри функции по профилю.

### 4. Bitrix24

1. Создайте входящий webhook с правами `tasks` и `user`.
2. Скопируйте URL в секрет `BITRIX_WEBHOOK_URL`.
3. Сотрудник, наставник и руководитель должны существовать в Bitrix24 с теми же email.
4. Задача создаётся методом `tasks.task.add`: ответственный — сотрудник, наблюдатели — наставник и руководитель.

Проверка прав и найденных пользователей выполняется при создании задачи. Если сотрудник не найден, приглашение всё равно создаётся, а ошибка попадает в список предупреждений и в журнал.

### 5. Фронтенд

1. Скопируйте `admin/`, `progress.html`, `js/supabase-client.js`, `js/vendor/supabase.js` в репозиторий.
2. В `js/supabase-client.js` и `progress.html` замените `ВАШ-ПРОЕКТ` и `ВАШ_PUBLISHABLE_ANON_KEY`.
3. Используйте **anon/publishable** ключ, не `service_role`.
4. Добавьте ссылку на `admin/` в основное меню книги.

## Как это работает

1. Администратор заполняет форму и отправляет приглашение.
2. Supabase создаёт пользователя со статусом «приглашён».
3. Система создаёт назначение курса и ссылку на прогресс сроком 365 дней.
4. В Bitrix24 создаётся задача «Пройти обучение» с наблюдателями.
5. Яндекс отправляет письмо со ссылкой для задания пароля.
6. Наставник и руководитель открывают прогресс по ссылке без входа в систему.
7. Сотрудник проходит модули, прогресс сохраняется в базе.

## Ограничения этого этапа

- Итоговый тест пока не перенесён в базу.
- Автоматическое обновление статуса задачи Bitrix24 при завершении курса — следующий этап.
- Страница входа `login.html` и восстановление пароля требуют отдельной вёрстки.
- RLS покрывает таблицы, но пути к файлам глав статичны и доступны всем — это учебные материалы, не секрет.

## Проверка перед публикацией

- [ ] Новый пользователь не может зарегистрироваться сам.
- [ ] Сотрудник не видит чужие назначения.
- [ ] Сотрудник не может изменить себе роль.
- [ ] Ссылка на прогресс не открывается после отзыва.
- [ ] Заблокированный пользователь не может войти.
- [ ] Письмо приходит и ссылка ведёт на задание пароля.
- [ ] Задача в Bitrix24 создаётся с нужными наблюдателями.
